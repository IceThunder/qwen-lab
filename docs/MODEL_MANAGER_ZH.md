# Web 模型管理：添加 Hugging Face 模型

## 开始使用

```bash
cd qwen-lab
bash scripts/web.sh
```

打开 http://127.0.0.1:7860/，点击顶部 **模型管理**。更新程序后，已有服务需要先 Ctrl+C 停止再启动；只刷新页面不会加载新后端接口。

1. 粘贴仓库首页，如 `https://huggingface.co/mlx-community/Qwen3.5-4B-4bit`，或填写 `作者/仓库名`。
2. 点击 **读取仓库**。界面显示固定提交版本、候选文件、下载大小、本机内存、可用磁盘空间及功能范围。
3. 选择版本，点击 **下载安装**。推荐优先选择在空间与权重体积估计范围内的 Q4_K_M 或 4-bit；推荐不保证运行性能或内存一定充足。
4. 在下载任务中查看进度，按需 **暂停下载 / 继续下载**。校验全部通过后，模型自动进入列表，不必编辑代码或配置文件。
5. 点击 **测试加载**。系统运行一次最多 16 token 的无干预文本推理，显示完成、失败或取消结果及具体错误。它使用与聊天相同的推理队列，不修改当前对话。
6. 关闭管理面板，在左侧模型列表中选择新模型，即可聊天。切换模型的已有会话处理与原来相同。

下载时可关闭管理面板，也可继续使用已安装模型。关闭 Web 服务会暂停下载；重新启动后打开管理面板，点“继续下载”。不需要重新输入原仓库链接，任务会保留固定版本。

## 第一版支持范围

| 类型 | 支持情况 |
|---|---|
| 无需登录的公开 Hugging Face 仓库 | 支持读取和下载 |
| 单文件 GGUF | 支持选择下载；文本推理能否运行由现有 llama.cpp 决定，需测试加载 |
| Qwen3.5 MLX 量化仓库 | 自动读取配置、权重分片索引，下载权重、分词器和相关配置 |
| 其他架构或普通 PyTorch safetensors | 未适配，不会冒充 MLX 模型安装 |
| GGUF 分片、多模态投影文件 mmproj | 第一版不安装，不提供图片输入 |
| 私有或 gated 模型、需要账户授权的仓库 | 第一版不支持，不接收或保存令牌 |
| 仓库远程 Python 自定义代码 | 不下载、不执行 |

MLX 识别条件包含 `model_type=qwen3_5/qwen3_5_text`、MLX 量化配置、有效层数及通道数，以及标准权重与分词器文件。即使匹配，仍需实际测试加载；社区仓库可能错误标注或使用当前框架尚不支持的配置。

GGUF 模型仅提供文本聊天，禁用现有 MLX 神经元控制。新 MLX 模型可使用已有架构的干预接口，但“测试加载”不验证神经元效果，也不会自动建立 Neuronary 配方匹配、创建 LoRA 训练配置或迁移适配器。

## 下载、续传与完整性

- 读取仓库时固定 commit SHA；下载与续传始终使用该提交，不跟随 main 的后续变化。
- 权重按 8 MiB 分块下载，最多 8 个并行请求。完成分块后持久保存进度；暂停后未完成分块可能需要重新下载。
- LFS 文件以完整 SHA256 校验，普通 Git 文件以 Git blob SHA1 校验；文件大小也必须匹配。
- 校验失败的当前文件重置后可重试；其他已完成文件保留。
- 全套文件校验成功后才原子发布到 `models/`。半成品位于 `work/`，不会提前被 Web 列为可用模型。
- 同仓库、同提交和同文件已安装时禁止重复下载，不覆盖旧目录。新版本或不同量化版本使用不同目录，可并存。
- 下载前检查剩余文件大小，并预留至少 1 GiB 磁盘空间。实际内存还包含运行时和上下文缓存，文件大小不是内存占用上限。
- 一次只下载一个模型任务。服务重启后下载保持暂停，需手动继续。

## 文件位置

```text
models/<仓库名-版本标识>/
├── weights/                完整权重、MLX 分词器及配置
├── source.json             仓库、固定提交、文件清单
├── checksum.json           文件哈希及校验结果
├── installation.json       模型管理安装标记及显示名称
├── runtime.json            仅 GGUF：文件与运行配置
└── load_test.json          执行“测试加载”后保存的结果

work/model-downloads/<任务ID>/
├── plan.json               固定版本的下载计划
├── state.json              进度及状态，重启后可恢复
├── package/                尚未完成的模型包（安装成功后已移入 models）
└── ranges/                 当前分块临时文件
```

不要清理仍需续传任务的 `work/model-downloads/`。当前界面不提供模型删除或运行时升级按钮，也不会删除已有权重。

程序实现：`web/model_manager.py`、`web/static/model-manager.js`。基础目录树见 README。

## 常见问题

- **读取仓库失败**：确认使用仓库首页，不含 `/tree/` 或 `/blob/`；检查网络、仓库是否公开且无需授权。
- **没有支持的版本**：查看提示。可能只有 GGUF 分片、非 MLX 配置或不支持的架构。
- **下载失败**：进度保留；网络恢复或空间释放后点“继续下载”。不支持 Range 或无法通过完整性校验的源不会被强行安装。
- **加载失败**：下载成功只代表文件完整。可能是 llama.cpp 不支持架构、MLX 配置不兼容、缺少聊天模板或内存不足。界面会显示错误；GGUF 详细日志为 `logs/llama-server.log`。
- **测试通过但正式对话异常**：测试只覆盖短文本加载与生成，不证明长上下文、特殊采样、多模态、神经元干预或微调有效。
- **新模型能聊天但不能导入 Neuronary 配方**：需要额外核对模型版本及权重来源，不能按参数量或层数自动匹配。

默认 `mlx-community/Qwen3.5-4B-4bit` 首次安装使用 `qwen3.5-4b` 目录，以便默认 CLI、LoRA 配置和 Neuronary 映射直接使用；已有默认目录时，其他版本使用单独标识。GGUF 需要另行安装 llama.cpp，例如 `brew install llama.cpp`。
